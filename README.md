# OSINT Toolkit

Графическое desktop-приложение на Python и Flet для пассивной OSINT-разведки, базовых проверок информационной безопасности и подготовки отчётов.

> Используйте инструмент только в законных целях и только для объектов и данных, которые вы имеете право проверять.

## Возможности

OSINT Toolkit объединяет несколько независимых проверок в одном интерфейсе:

| Инструмент | Что проверяет |
|---|---|
| **IP-адрес** | Геолокацию, провайдера и организацию, AS, reverse DNS, признаки proxy/VPN/Tor, hosting/mobile; дополнительно — открытые порты, CVE, hostname и CPE через Shodan InternetDB |
| **Домен** | DNS-записи A/AAAA/MX/NS/TXT, SPF, DMARC, данные регистрации RDAP и поддомены из сертификатов `crt.sh` |
| **E-mail** | MX-записи, репутацию и признаки злоупотребления через EmailRep.io, публичный профиль Gravatar |
| **Ник** | Поиск одинакового username на 16 площадках с фильтрами по категориям |
| **Пароль** | Проверку наличия пароля в базе Have I Been Pwned с использованием k-anonymity, а также приблизительную оценку стойкости |
| **Заголовки сайта** | HTTP-заголовки безопасности, `Server`, `X-Powered-By` и флаги `Secure`/`HttpOnly` у cookie |
| **Web Archive** | Историю снимков сайта/страницы через CDX API Internet Archive |
| **Хэш файла** | MD5, SHA-1, SHA-256 и поиск хэша в CIRCL Hash Lookup; формирует ссылку на VirusTotal |
| **Фото** | EXIF-метаданные, сведения о камере/ПО/дате и GPS-координаты, если они присутствуют |
| **Декодер** | JWT, Base64, hex, URL-кодирование, Punycode и безопасную форму URL для отчётов |
| **VK-связи** | Анализ открытых данных VK: друзья, сообщества, пересечения и интерактивный граф связей |

## Требования

- Python 3.9+ рекомендуется.
- Интернет требуется для сетевых проверок.
- Основные зависимости:

```bash
pip install flet requests
```

Для инструмента **Фото** дополнительно нужен Pillow:

```bash
pip install pillow
```

## Установка

Клонируйте или скачайте проект и установите зависимости:

```bash
git clone <URL-репозитория>
cd <каталог-проекта>

python -m pip install flet requests pillow
```

Сам скрипт можно сохранить, например, как:

```text
osint_toolkit.py
```

## Запуск

```bash
python osint_toolkit.py
```

Приложение запускается как графический интерфейс Flet.

В интерфейсе доступны:

- боковая панель с инструментами;
- поле ввода цели;
- контекстные фильтры;
- фильтрация результатов по уровню (`Критично`, `Проблемы`, `В порядке`);
- журнал выполненных проверок;
- заметки по делу;
- экспорт отчёта;
- сохранение и загрузка дела.

## Использование инструментов

### IP-адрес

Пример:

```text
8.8.8.8
```

Также можно указать доменное имя:

```text
example.com
```

Поддерживаются режимы:

- всё;
- геолокация и сеть;
- порты и CVE.

Если поле оставить пустым, программа использует внешний IP-адрес запроса.

### Домен

Пример:

```text
example.com
```

Можно отдельно просматривать:

- DNS;
- регистрацию;
- поддомены.

Для поддоменов доступен текстовый фильтр, например:

```text
mail
```

### E-mail

Пример:

```text
name@example.com
```

Проверяются:

- MX-записи домена;
- репутация адреса;
- подозрительность;
- признаки вредоносной активности;
- публичные аккаунты/профиль, если они доступны через используемые сервисы.

### Ник

Пример:

```text
username
```

Проверяются следующие площадки:

- GitHub
- GitLab
- Bitbucket
- Codeberg
- Docker Hub
- PyPI
- Dev.to
- Habr
- Hacker News
- Keybase
- Reddit
- SoundCloud
- Gravatar
- Telegram
- Lichess
- Chess.com

Можно выбрать категорию площадок и при необходимости показывать ненайденные профили.

> Совпадение username само по себе не доказывает, что найденные аккаунты принадлежат одному человеку. Результаты необходимо сверять вручную.

### Пароль

Ввод пароля выполняется в скрытом поле.

Для проверки используется механизм k-anonymity: наружу передаётся только первые 5 символов SHA-1 хэша пароля, после чего локально определяется совпадение с полученным диапазоном.

Результат содержит:

- количество обнаружений в известных утечках;
- длину;
- приблизительную энтропию;
- рекомендацию по дальнейшим действиям.

Не используйте этот инструмент для передачи чужих паролей или секретов.

### Заголовки сайта

Пример:

```text
example.com
```

Проверяются, в частности:

- `Strict-Transport-Security`
- `Content-Security-Policy`
- `X-Frame-Options`
- `X-Content-Type-Options`
- `Referrer-Policy`
- `Permissions-Policy`

Также анализируются cookie и наличие флагов `Secure` и `HttpOnly`.

### Web Archive

Пример:

```text
example.com/page
```

Можно задать диапазон годов:

```text
С года: 2019
По год: 2024
```

Инструмент показывает первый и последний найденный снимок и активность по годам.

### Хэш файла

Можно передать:

```text
C:\files\setup.exe
```

или готовый хэш:

```text
SHA-256
```

Для файла программа вычисляет:

- MD5;
- SHA-1;
- SHA-256.

После этого хэш проверяется через CIRCL Hash Lookup. Если файл известен эталонным базам, отображаются доступные сведения.

Также формируется ссылка на VirusTotal.

### Фото

Поддерживаются:

```text
jpg
jpeg
png
tiff
webp
heic
```

Извлекаются доступные EXIF-данные:

- производитель;
- модель камеры;
- объектив;
- программа;
- дата съёмки;
- автор;
- GPS.

Если в EXIF присутствуют координаты, программа показывает их и формирует ссылку на OpenStreetMap.

> Перед публикацией фотографий проверяйте EXIF: GPS-координаты могут раскрыть место съёмки.

### Декодер

Инструмент работает офлайн и распознаёт:

- JWT;
- Base64;
- hex;
- URL encoding;
- Punycode;
- `hxxp` и `[.]`-обфускацию URL.

Для JWT отображаются заголовок, payload и срок действия, если они доступны. Подпись JWT программой не проверяется.

Для обычных URL инструмент может сформировать безопасную форму вида:

```text
hxxps://example[.]com
```

что удобно для вставки вредоносных или подозрительных адресов в отчёты.

## VK-связи

Инструмент **VK-связи** использует открытые данные через VK API и строит интерактивный HTML-граф.

Поддерживаются режимы:

- **Всё вместе**
- **Только друзья**
- **Только сообщества**

Дополнительные фильтры:

- минимальное количество друзей в сообществе;
- пол;
- город;
- скрытие друзей без связей.

Граф поддерживает:

- перетаскивание узлов;
- закрепление и открепление узлов;
- поиск;
- фильтрацию друзей и сообществ;
- фильтрацию типов связей;
- фильтрацию по кругам общения;
- отображение аватарок;
- масштабирование;
- вписывание графа в окно;
- сохранение текущего вида в SVG;
- открытие профиля/сообщества VK из панели деталей.

### Получение VK service key

Для VK-модуля нужен **сервисный ключ приложения**.

В программе есть кнопка **«Получить ключ»**, которая показывает пошаговую инструкцию и позволяет открыть страницы создания/управления приложениями VK.

Ключ можно:

1. ввести в интерфейсе;
2. проверить кнопкой **«Проверить ключ»**;
3. либо передать через переменную окружения:

```bash
VK_TOKEN=your_service_key
```

В Windows PowerShell:

```powershell
$env:VK_TOKEN="your_service_key"
python osint_toolkit.py
```

Ключ хранится в памяти программы и не записывается самим приложением в файл конфигурации.

> VK API может ограничивать доступ отдельных методов для сервисных ключей. Закрытые профили программа не обходит, поэтому результаты анализа могут быть неполными.

## Источники данных

Проект обращается к внешним сервисам, в частности:

- `ip-api.com`
- `Shodan InternetDB`
- `dns.google` (DNS-over-HTTPS)
- `rdap.org`
- `crt.sh`
- `EmailRep.io`
- `Gravatar`
- `Have I Been Pwned / Pwned Passwords`
- `web.archive.org`
- `hashlookup.circl.lu`
- `VirusTotal` — используется как ссылка для дальнейшей проверки хэша
- VK API — только для отдельного инструмента VK и при наличии service key

Большинство основных OSINT-проверок не требуют регистрации или API-ключей. Исключение — VK-модуль.

## Отчёты и дела

После каждой проверки результат добавляется в локальный **журнал дела**.

Доступны:

### Markdown

Отчёт содержит:

- дату и время;
- заметки;
- выполненные инструменты;
- цели;
- применённые фильтры;
- результаты по разделам.

### HTML

HTML-отчёт содержит те же данные в более удобном для просмотра виде. URL в результатах превращаются в кликабельные ссылки.

### JSON

Сохранение дела в JSON позволяет позднее загрузить журнал вместе с заметками и результатами проверок.

Пример структуры:

```text
osint_report_YYYYMMDD_HHMM.html
osint_case_YYYYMMDD_HHMM.json
```

## Архитектура

Проект реализован как один Python-скрипт.

Основные части:

```text
OSINT Toolkit
├── сетевые помощники
├── инструменты OSINT/ИБ
│   ├── IP
│   ├── Domain
│   ├── E-mail
│   ├── Username
│   ├── Password
│   ├── Headers
│   ├── Web Archive
│   ├── Hash
│   ├── Photo
│   └── Decoder
├── VK API и граф связей
├── фильтры запросов
├── фильтры результатов
├── журнал дела
├── Markdown/HTML отчёты
├── JSON сохранение/загрузка
└── Flet GUI
```

Каждый основной инструмент возвращает результат в унифицированном виде:

```python
[
    (
        "Название секции",
        [
            ("Поле", "Значение", "ok"),
            ("Предупреждение", "Значение", "warn"),
            ("Проблема", "Значение", "bad"),
        ],
    )
]
```

Это позволяет одному интерфейсу отображать результаты разных проверок и использовать их для журналирования и отчётов.

## Безопасность и приватность

Проект предназначен для **пассивной разведки и проверок**. Он не должен использоваться для:

- обхода авторизации;
- доступа к закрытым профилям;
- эксплуатации уязвимостей;
- получения чужих секретов;
- нарушения законодательства или правил используемых сервисов.

Некоторые проверки отправляют введённые данные или производные от них данные во внешние сервисы. Перед использованием учитывайте политики конфиденциальности соответствующих сервисов.

Особенно внимательно относитесь к:

- e-mail адресам;
- IP-адресам;
- фотографиям с EXIF;
- файлам;
- паролям;
- VK service key.

Парольная проверка реализована так, чтобы сам пароль не отправлялся в HIBP: используется префикс SHA-1 в рамках k-anonymity.

## Ограничения

Результаты OSINT-сервисов не являются абсолютным доказательством.

Например:

- геолокация IP не определяет точный физический адрес пользователя;
- совпадение username не подтверждает личность владельца;
- отсутствие записи в базе не означает отсутствие компрометации;
- отсутствие EXIF не означает отсутствие метаданных в других источниках;
- данные DNS/RDAP/сертификатов зависят от доступности и актуальности внешних сервисов;
- VK-данные ограничены тем, что разрешает API и что опубликовано пользователями.

Внешние сервисы могут иметь rate limits, временные сбои или изменять свои API.

## Troubleshooting

### `ModuleNotFoundError: No module named 'flet'`

```bash
python -m pip install flet
```

### `ModuleNotFoundError: No module named 'requests'`

```bash
python -m pip install requests
```

### Ошибка при работе с фотографией

Установите Pillow:

```bash
python -m pip install pillow
```

### Сетевые ошибки

Проверьте:

- подключение к интернету;
- DNS;
- firewall/proxy;
- доступность внешнего сервиса;
- временные ограничения API.

### VK отклоняет ключ

Убедитесь, что используется именно **сервисный ключ доступа** приложения и что приложение включено. Некоторые методы VK недоступны для service key — в таком случае результат будет неполным.
